# AGENTS.md

Руководство для AI-агентов и новых разработчиков, работающих с репозиторием.

## Что это за проект

`warpgen` — локальный CLI-инструмент на Go: регистрирует WARP-аккаунт, перебирает
рабочие endpoint Cloudflare, проверяет DNS через туннель и генерирует `.conf` для
AmneziaWG (WireGuard + обфускация). Туннель — **userspace**, без root, без TUN и
без изменения маршрутов системы. Поверх CLI есть приложения на Flutter для Linux
и Windows
(`gui/`) — только оболочка, весь туннель по-прежнему в Go-бинарнике.

Подробности замысла: `README.md`. Эталонные конфиги: `refconf/` (в git не попадают,
см. «Секреты»).

## Быстрые команды

```bash
make build            # статический бинарник ./warpgen (CGO_ENABLED=0)
make build-debug      # без -s -w
make test             # go test ./... -short
make vet              # go vet ./...
make fmt              # gofmt -l . (показать неотформатированное)
make checks           # vet + fmt + test
make test-integration # реальная сеть, за флагом (в CI не гонять)
make test-e2e         # сетевые проверки пайплайна run (тег e2e, вручную)
make gui-deps         # flutter pub get для gui/
make gui-test         # офлайн-тесты GUI (фейковые процессы, без сети)
make gui-test-live    # live-e2e GUI: сеть, настоящий CLI и SOCKS5
make gui-analyze      # flutter analyze
make gui-run          # запустить GUI (нужны Flutter SDK и GTK3 dev)
make gui-build        # релизная сборка Linux-приложения
make android-apk      # APK arm64: Go-ядро + VpnService + warp-plus внутри
make windows          # портативная Windows-сборка: exe + zip (только на Windows)
make clean            # удалить артефакты сборки
```

Перед сдачей любой правки обязательно зелёные: `go build ./...`, `go vet ./...`,
`gofmt -l .` (пусто), `go test ./... -short`. Пользователь код не читает — ревью
идёт только через тесты и поведение инструмента.

Правка в `gui/` дополнительно требует зелёных `make gui-analyze` и `make gui-test`
(`make checks` покрывает только Go).

### Офлайн-режим

Модули лежат в локальном кэше, поэтому сборка/тесты работают так:

```bash
GOPROXY=off go build ./...
GOPROXY=off go test ./... -short
```

`go mod tidy` в этом окружении **не отрабатывает** (в кэше нет `.zip`/`.mod` для
части транзитивных зависимостей вроде `wintun`/`coninput`). Не «лечите» это
удалением зависимостей из `go.mod` — версии подобраны под кэш. На машине с сетью
достаточно один раз прогнать `go mod tidy`.

## Структура пакетов

| Пакет | Ответственность |
|---|---|
| `registration/` | неофициальный API Cloudflare, регистрация WARP, локальное хранение аккаунта |
| `tunnel/` | userspace WireGuard/AmneziaWG, хендшейк, `cdn-cgi/trace`, замер задержки, платформенный bind |
| `scanner/` | кандидаты (диапазоны × порты), предфильтр хендшейком, фильтр региона/colo, ранжирование |
| `dnscheck/` | проверка DNS через туннель |
| `config/` | сборка `.conf` (WARP-safe) и генераторы `I1` |
| `chain/` | цепочка «внешний AWG-туннель → WARP → Psiphon»: запуск внешнего warp-plus, проверка SOCKS5 |
| `core/` | пайплайн команды `run`: автомат состояний (endpoint → туннель → форвардер → страны → мониторинг), UDP-форвардер, поток событий |
| `vpn/` | системный туннель `run --tun`: TUN-устройство, мост TUN→SOCKS5 на gVisor netstack, DNS через цепочку, маршруты и откат (Linux) |
| `services/` | проверка доступности сервисов через SOCKS5 (без влияния на туннель) |
| `cli/` | CLI-команды `register`, `scan`, `dns-check`, `dns-presets`, `dns-current`, `services`, `gen`, `chain`, `run`, `tun-revert` |
| `cmd/warpgen/` | точка входа, версия (подставляется через ldflags) |
| `gui/` | Flutter/GUI для Linux и Windows (Material You): обёртка над CLI, своей сетевой логики нет |

Правило: логика — в пакетах, `cli/` только собирает их вместе и печатает.
Внутренние детали (`internal/`) не заводим — это локальный инструмент.

### GUI (пакет `gui/`, Flutter)

- GUI — только оболочка: он запускает бинарник `warpgen` и разбирает его машинный
  вывод (`run --json` — NDJSON, `dns-presets`/`dns-current`/`services` — один
  документ). Логику туннеля, DNS, проверки сервисов и конфигов в Dart не
  переносить: второй реализации быть не должно.
- Процессы запускаются только через `ProcessRunner` (`gui/lib/src/platform/`),
  фейки — `gui/test/support/fakes.dart`. Тесты GUI — офлайн: без сети, без реальных
  процессов и без root. Новый системный эффект — только через этот интерфейс.
- Остановка — SIGINT (Go успевает снять туннель и дочерние процессы), SIGKILL —
  только по таймауту. Для root-процесса (`--tun` через `pkexec`) SIGINT недоступен:
  GUI пишет файл-сигнал (`--stop-file`), а CLI сам завершает пайплайн. Никаких
  `os.Exit`-подобных решений в контроллерах.
- Главный экран — одна кнопка подключения, режим WARP/WARP + Psiphon, TUN и
  терминальный блок состояния. Все настройки — во второй горизонтальной вкладке;
  сканера в GUI нет, отдельный `.conf` не создаётся.
- Настройки GUI — `~/.warpgen/gui.json` (только выбор пользователя, без ключей).
  Аккаунт создаётся автоматически при первом включении; «Пересоздать
  конфигурацию» делает `register --fresh`, удаляет identity warp-plus и профиль
  endpoint'ов `~/.warpgen/endpoints.json` (чтобы следующий запуск снова выбрал их
  по скорости).
- Приватный ключ аккаунта в интерфейс не попадает: `AccountInfo` его не содержит,
  в журнал и snackbar’ы уходят только адреса, страны и пути к файлам.
- Тема — Material 3 (`useMaterial3`, `ColorScheme.fromSeed`), без внешних
  UI-пакетов. Новые зависимости — только по явной необходимости.
- SDK Flutter локальный: `.toolchain/` в корне проекта и в `.gitignore`; основной
  диск трогать не нужно. `make gui-*` сам подставляет `FLUTTER` и `PUB_CACHE`
  (кэш пакетов — `.toolchain/pub-cache`), поэтому в этом окружении хватает
  `make gui-deps` без сети: `flutter pub get --offline` разрешается из кэша SDK.
- Сборка Linux-приложения требует GTK3 dev: `libgtk-3-dev` (тянет glib/pango/
  cairo/gdk-pixbuf dev) плюс `clang`, `cmake`, `ninja-build`, `pkg-config`.
  Без них `make gui-build` падает на `pkg_check_modules(gtk+-3.0)` — это
  окружение, а не код.
- `make gui-run` передаёт `WARPGEN_BIN=$(CURDIR)/warpgen`: GUI запускается из
  `gui/`, и без этого путь к бинарнику в корне не находится.
- В `gui/linux/CMakeLists.txt` установка `native_assets` обёрнута в `if(EXISTS …)`:
  шаблон Flutter 3.47 безусловно копирует этот каталог, а у приложения без native
  assets его нет — чистая сборка падала на `file INSTALL cannot find`. Не убирать;
  при `flutter create`/обновлении SDK проверить, что правка осталась.
- Если первая конфигурация CMake упала (например, не было GTK), в кэше
  `gui/build` застревает `CMAKE_INSTALL_PREFIX=/usr/local`, и шаблон больше не
  переопределяет его на `bundle/` — установка падает с `Permission denied`.
  Лечение: `rm -rf gui/build` и собрать заново.

### Windows (пакет `gui/windows/`)

- Та же Dart-оболочка, отдельный runner. Сборка — `make windows`
  (`scripts/build-windows.sh`): Go-ядро под `windows/amd64` с выключенным CGO,
  релиз warp-plus для windows-amd64, `wintun.dll` 0.14.1 (скачивается при сборке,
  в git не лежит), `flutter build windows --release` и zip. Установщика нет:
  содержимое `Release/` распаковывается куда угодно и запускается с
  `warpgen_gui.exe`; реестр не трогается.
- `warpgen.exe`, `warp-plus.exe` и `wintun.dll` кладутся рядом с `warpgen_gui.exe`:
  GUI ищет CLI рядом с собой (`WarpgenLocator`), CLI — warp-plus рядом с собой
  (`chain.ResolveWarpPlus`), а `golang.zx2c4.com/wintun` ищет DLL только в
  каталоге приложения и System32. Имя бинарника на Windows — `warpgen.exe`,
  элементы `PATH` разделены `;`.
- Системный туннель есть: `vpn/tun_windows.go` создаёт Wintun-адаптер через
  `amneziawg-go/tun`, `vpn/routes_windows.go` настраивает адрес, маршруты
  `0.0.0.0/1` + `128.0.0.0/1`, `::/0` (IPv6 уводится в TUN и отбрасывается),
  исключение endpoint и системный DNS через PowerShell (`Get-NetRoute`,
  `New-NetRoute`, `Set-DnsClientServerAddress`) — без разбора локализованного
  `netsh`. Переключатель TUN виден (`Platform.isLinux || Platform.isWindows`), на
  первом запуске включён; выбор хранится в `gui.json`.
- GUI запускается с `requireAdministrator`. Уровень задаётся
  `target_link_options(... /MANIFESTUAC:...)` в `gui/windows/runner/CMakeLists.txt`,
  а не `trustInfo` в `runner.exe.manifest`: CMake уже отдаёт манифест линкеру с
  `asInvoker`, и второй `level` ломает `mt.exe` (`manifest authoring error
  c1010001`). `warpgen.exe` наследует права, `vpn.CheckPrivileges` проверяет
  elevation до сети.
- Данные портативные: настройки, аккаунт, `endpoints.json`, `chain/`, `state/` и
  `run/` лежат в `warpgen-data` рядом с `warpgen_gui.exe` (`AppPaths`,
  `AppDependencies`). Если туда нельзя писать — откат в `%USERPROFILE%\.warpgen`.
  `--state-dir`, `--endpoint-cache`, `--cache-dir`, `--account` и `--stop-file`
  GUI передаёт явно, поэтому CLI не пишет в профиль.
- Мягкая остановка — файлом-сигналом `--stop-file`: в `dart:io` на Windows нельзя
  доставить SIGINT дочернему процессу (`Process.kill` = `TerminateProcess`).
  Поэтому `WarpgenCli.softStopByFile` включён на Windows, а обёртка —
  `StopFileRunningProcess` (без дублирующего сигнала); SIGKILL — по таймауту.
- `dns-current` работает: `vpn.ReadCurrentDNS` читает серверы интерфейса
  маршрута по умолчанию через PowerShell, поэтому пресет «DNS провайдера» доступен.
  Домашний каталог берётся из `USERPROFILE`.
- Тесты Go должны быть зелёными и на Windows: Linux-only тесты системного
  туннеля лежат в файлах с `//go:build linux` (`vpn/tunnel_linux_test.go`,
  `cli/tun_test.go`), проверки POSIX-прав пропускаются на Windows, а
  Windows-маршруты проверяются офлайн в `vpn/routes_windows_test.go` на фейковом
  `vpn.Executor` (создавать реальный TUN в тестах нельзя).

### Android (пакет `gui/android/`)

- Android-версия — та же Dart-оболочка, но TUN создаёт `WarpgenVpnService`, а не
  CLI под root. Go-ядро собирается под `android/arm64` как `libwarpgen.so` и
  запускается отдельным процессом из `nativeLibraryDir`; fd TUN передаётся по
  unix-сокету через `SCM_RIGHTS` (флаг `run --tun-fd-socket`).
- `libwarpgen.so` и `libwarp-plus.so` в git не лежат (`.gitignore`): их собирает
  `scripts/build-android.sh` (`make android-apk`). `libwarp-plus.so` — официальный
  android-arm64 релиз warp-plus v1.2.6, нужен режиму WARP + Psiphon.
- Приложение исключено из своего VPN (`addDisallowedApplication`): исходящие
  сокеты Go-процесса идут напрямую, петли нет, `VpnService.protect` не нужен.
  Адрес/маршруты/DNS задаёт VpnService, поэтому `vpn/routes_android.go` — заглушка,
  а `vpn/privileges_android.go` не требует root.
- `--tun` на Android включается всегда; переключатель скрыт. `dns-current` и
  «DNS провайдера» на Android недоступны — это не ошибка, DNS задаёт VpnService.
- APK только `arm64`, подпись debug-ключом. Сборка и установка — вручную
  (`adb install -r`), в `make checks` не входят; эмулятор не нужен.
- Android-код не должен протекать в Linux: `WarpgenCli.startRun` выбирает ветку
  по `Platform.isAndroid`, `AndroidProcessRunner` — только для `run --tun`.
- Потоки чтения stdout/stderr в `WarpgenVpnService` обязаны глотать
  `IOException`: при отключении `stopVpn()` закрывает поток из другого потока,
  и необработанный `InterruptedIOException` роняет всё приложение (проверено
  на Honor/Huawei).
- Go-резолвер на Android (netgo, CGO выключен) читает `/etc/resolv.conf` с `::1`
  и не видит системный DNS. Поэтому `cli/dns_resolve_android.go` подменяет
  `net.DefaultResolver` на публичные `1.1.1.1`/`8.8.8.8`/`9.9.9.9`; без этого
  первый запуск падает на регистрации «API Cloudflare недоступен», а замер
  скорости не может открыть `speed.cloudflare.com`. `77.88.8.8` для этого не
  использовать: в РФ он отдаёт для API подменённый `8.47.69.0`.

## Жёсткие инварианты — не ломать

### Конфиг WARP-safe (пакет `config`)

Обычный сервер Cloudflare не знает про AmneziaWG, поэтому менять формат пакетов
нельзя. Эти значения зафиксированы и проверяются тестами:

- `S1 S2 S3 S4 = 0`, `H1 H2 H3 H4 = 1 2 3 4` — выводятся в конфиг **всегда**;
- `MTU = 1280`;
- `PersistentKeepalive = 25` — **в секции `[Peer]`**, не в `[Interface]`;
- `I1` — имя поля строго заглавными, значение маскирует трафик (QUIC и др.);
- `DNS =` принимает **только IP** — имена резолвятся заранее;
- порядок полей `[Interface]`/`[Peer]` — как в `refconf/`.

Любые «улучшения» вроде своих `S`/`H`-значений или смены MTU ломают связь с
неизменённым сервером Cloudflare. Не делать.

### Туннель

- По умолчанию только userspace: обычные UDP-сокеты + netstack. **Никаких** root, TUN,
  `VpnService`, смены маршрутов.
- Единственное исключение — явный флаг `run --tun`: он поднимает системный TUN и
  меняет маршруты. Это изолировано в пакете `vpn/`, включается только флагом и не
  должно протекать в остальные команды (`register`, `scan`, `dns-check`, `gen`,
  `chain`, `run` без `--tun`). На Windows для этого нужны Wintun и права
  администратора, на Linux — root; без них `--tun` падает до сети и системных
  действий.
- Задержку мерить **внутри туннеля**, не через ICMP/Ping (на Android ICMP
  ограничен и без прав показывает `?`).
- Не добавлять linux-only syscall'ы вне файлов с build tags
  (`tunnel/bind_linux.go`, `tunnel/bind_other.go`).

### Скан

- Диапазоны: `162.159.192.0/24`, `162.159.193.0/24`, `188.114.96.0/22`.
- Порты: `500, 1701, 4500, 2408`.
- Исключать регион `RU` и colo `DME`, `LED`, `KJA`.
- Полный перебор — тысячи пар IP×порт; за прогон проверяем `--max` кандидатов и
  останавливаемся после `--target` находок. Не превращать скан в долгий полный обход.
- Любой автоподбор endpoint (например, в `dns-check` без `--endpoint`) обязан быть
  ограничен по числу проверок и/или времени — иначе он уйдёт перебирать тысячи адресов.

### Пайплайн `run` (пакет `core`)

- `core` — библиотека: **никаких** `os.Exit`, чтения stdin, печати в stdout и
  глобального состояния. Остановка — только по `ctx`, диагностика — через
  `Config.Logf`. GUI и мобильные клиенты позже будут обёртками над этим API.
- Внешние зависимости (туннель, поиск endpoint, запуск warp-plus, проверка выхода,
  часы) заданы интерфейсами `Config`; фейки — в `core/fakes_test.go`. Новый сетевой
  эффект добавлять только через них, иначе автомат перестанет тестироваться офлайн.
- Внешний туннель отдаётся наружу только через UDP-форвардер, и только на loopback
  (проверяется в `NewForwarder`): форвардер даёт доступ к туннелю без аутентификации.
  `warp-plus` получает адрес форвардера в `-e`.
- Режим `--warp-only` (`Options.WarpOnly` / `Config.Direct`) — без Psiphon: наружу
  отдаётся локальный SOCKS5 (`core/socks.go`) прямо поверх внешнего WARP-туннеля.
  Слушает только loopback, занимает один порт на весь прогон (при failover
  `SetTunnel` меняет туннель, а не адрес). Выход RU здесь ожидаем: мониторинг
  страну не меняет, а после трёх сбоев пересоздаёт туннель на следующем endpoint'е.
  В этом режиме `Chain`/`Countries` не нужны, preflight проверяет только аккаунт.
- Проверка выхода разделена: жива ли связь (обычный HTTPS-запрос через SOCKS5) и
  какую страну видит выход (геосервисы). Молчание геосервисов при живой связи —
  `Services=0` без ошибки: звено не меняем, только `degraded`.
- Мониторинг инерционный: смена звена — только после серии неудачных проверок
  подряд (`MonitorFailures` / `TraceFailures` / `RUFailures`, по умолчанию 5/3/3),
  одиночная просадка — только событие `degraded`. Не возвращать переключение по
  первой же ошибке: с `--tun` мгновенный failover выглядит как обрыв интернета,
  пока поднимается новое звено.
- MTU внешнего туннеля — 1280. Пакеты больше MTU считаем как `oversize` (счётчик +
  запись в `Logf`) и передаём как есть: процесс не роняем.
- Профиль endpoint'ов (`Config.ProfilePath`, CLI `--endpoint-cache`) — первый
  запуск сканирует и меряет скорость через итоговый выход (в Direct — WARP, с
  Psiphon — цепочку), сортирует по ней и сохраняет; следующие запуски не
  сканируют и не меряют. Профиль не содержит ключей. Замер — новый сетевой эффект,
  поэтому идёт только через `Config.SpeedTest` (в тестах подменяется).
- События (`endpoint_selected`, `outer_up`, `outer_checked`, `speed_testing`,
  `speed_checked`, `forwarder_up`, `psiphon_starting`, `ready`, `degraded`,
  `failover`, `stopped`) — публичный контракт CLI и будущих клиентов: имена не
  менять без нужды, секретов в них нет.
- Сетевые проверки пайплайна — за тегом `e2e` (`core/e2e_run_test.go`), в
  `go test ./...` они не попадают. Обычные тесты — только loopback (локальное
  UDP-эхо) и фейки, без обращений во внешнюю сеть.

### Системный туннель `--tun` (пакет `vpn`)

- Системные эффекты — только через интерфейсы: `Config.TUN` в `core` (фейк —
  `core/fakes_test.go`), `vpn.Device`, `vpn.RouteManager`, `vpn.Executor`.
  `os/exec` живёт только в `vpn/routes_linux.go`; в остальном коде `vpn` никаких
  команд и syscall'ов быть не должно.
- TUN создаётся только через пакет `tun` из `amneziawg-go`: `CreateTUN` для root
  и `CreateUnmonitoredTUNFromFD` для готового fd от Android VpnService. Второй
  вариант не делает `SIOCSIFMTU`/netlink — у Android-приложения нет
  `CAP_NET_ADMIN`, а MTU уже задан `VpnService.Builder`. Ручных ioctl нет.
- Маршруты применяются **только после** `ready`, иначе мост работает без прокси.
  Порядок запуска: цепочка → TUN и мост → маршруты → DNS; остановка — в обратном
  порядке, и всегда снимает маршруты (откат не зависит от отмены `ctx`).
- `RouteManager` помнит каждую выполненную команду и отменяет ровно их (обратный
  порядок); ошибка посередине откатывает применённое. `--dry-run` ничего не
  выполняет.
- После каждой выполненной команды журнал отката атомарно пишется в
  `~/.warpgen/state/<имя TUN>.st` (каталог — `Options.StateDir`), поэтому
  `kill -9` не оставляет применённое без записи. Команда `warpgen tun-revert`
  (`vpn.RevertTunState`) откатывает по журналу: невыполненные отмены остаются
  в файле (повтор продолжает с места сбоя), полностью откаченное удаляется.
  Шаги, чья отмена упала с «цели уже нет» (интерфейс уничтожен вместе с
  процессом), не считаются сбоем — см. `linuxTolerate`.
- Исключение `/32` внешнего endpoint — не оптимизация, а защита от петли: без него
  UDP-сокет внешнего туннеля уйдёт в наш же TUN. При смене endpoint обновлять.
- При failover TUN и маршруты **не снимать**: падающие соединения — это kill switch,
  трафик не должен уходить напрямую.
- UDP не проксируется, поэтому QUIC (`UDP/443`) отбрасывается молча (приложения
  должны откатываться на TCP), IPv6 уводится в blackhole, ICMP отбрасывается.
  Новое поведение для UDP сначала согласовать: точка расширения — `handleUDP`.
- События `tun_up`, `routes_applied`, `routes_reverted`, `dns_selected`, `dns_failed`
  — часть публичного контракта (наравне с остальными), имена не менять без нужды.
- Без root режим `--tun` обязан упасть с понятным сообщением до сети и до любых
  системных действий; проверка прав — `vpn.Options.CheckPrivileges` (Android её
  подменяет). CLI дополнительно вызывает `vpn.CheckPrivileges` до резолва
  DNS-hostname'ов, чтобы не ходить в сеть без root.
- Тесты `vpn` — офлайн: мост на двух стеках через фейковое устройство и поддельный
  SOCKS5, политика пакетов, выбор DNS, `RouteManager` на фейковом исполнителе. Тестов,
  которые создают TUN, меняют маршруты или просят root, в репозитории быть не должно:
  это ручной чек-лист e2e в README.

### Важно про регион RU (проверено на реальной сети)

Из России WARP **всегда** показывает внешним сервисам регион `RU`: Cloudflare
назначает выходной IP по геолокации клиента, а не по узлу `colo`. Замер: 100
endpoint'ов, 77 отдали trace, из них `loc=RU` — у всех; `ipinfo.io` и `ifconfig.co`
через туннель тоже видят Россию.

Решение пользователя: такие endpoint'ы **учитываются** (регион `RU` — не повод для
отбраковки). Реализовано так: `Options.StrictRegion` (по умолчанию `false`) и флаг
`scan --strict-region` для жёсткого режима; функция `regionStatus` применяет
политику, `ClassifyRegion` остаётся чистой. Исключённые colo DME/LED/KJA
отвергаются всегда — это вопрос доступности, а не региона. Не возвращать
безусловный фильтр `loc != RU` без явного запроса.

## Секреты и приватность

В git **не должно** попадать ничего с приватными ключами. Уже в `.gitignore`:
`refconf/`, `test-account.json`, `warpgen-account.json`, `*-account.json`, `*.conf`
(сгенерированные конфиги тоже содержат приватный ключ), `warpgen-chain/` (identity
warp-plus для команды `chain`), бинарники, `coverage.out`, локальные `.md`-документы.

При добавлении новых выходных файлов с ключами — сразу заносить в `.gitignore`.
Перед коммитом проверять, что в индекс не попали ключи и токены.

GUI (`gui/`) ключей не создаёт и не копирует: конфиги из «Скана» пишутся в
`~/.warpgen/conf/` (вне репозитория), identity warp-plus — в `~/.warpgen/chain`.
В `.gitignore` есть `/.toolchain/` (локальный SDK Flutter) и артефакты GUI
(`/gui/build/`, `/gui/.dart_tool/`, `/gui/linux/flutter/ephemeral/`).

## Известные ограничения

- **Режим WARP + Psiphon сейчас не работает** (проверено live 26.10.2026):
  Psiphon-этап падает, выхода вне РФ нет. Фиксить пока **не будем** — это
  осознанное решение, а не забытая задача; рабочий режим `--warp-only`.
  Не чинить без явной задачи.
- Если на устройстве активен другой VPN, скан пойдёт через него — проверять при
  выключенном VPN.
- Регистрация через туннель (когда API Cloudflare недоступен напрямую) требует уже
  существующего аккаунта (`--account`).
- Тесты GUI только офлайн (`make gui-test`): окно и оболочка проверены, а
  «Подключиться → туннель → проверка сервисов» — live-чек-лист (`make
  gui-test-live`, нужны сеть, аккаунт и настоящий `./warpgen`).
- Фичи вне v1: split-tunneling, кастомный клиент, macOS-версия GUI (сейчас есть
  Linux, Windows и Android в `gui/`), релеи, warp-in-warp, MASQUE.
- Сквозная проверка «импортировали в AmneziaVPN → соединение поднялось → `loc != RU`»
  делается руками на устройстве.
