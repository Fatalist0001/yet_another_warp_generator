# AGENTS.md

Руководство для AI-агентов и новых разработчиков, работающих с репозиторием.

## Что это за проект

`warpgen` — локальный CLI-инструмент на Go: регистрирует WARP-аккаунт, перебирает
рабочие endpoint Cloudflare, проверяет DNS через туннель и генерирует `.conf` для
AmneziaWG (WireGuard + обфускация). Туннель — **userspace**, без root, без TUN и
без изменения маршрутов системы.

Подробности замысла: `README.md`. Эталонные конфиги: `refconf/` (в git не попадают,
см. «Секреты»).

## Быстрые команды

```bash
make build            # статический бинарник ./warpgen (CGO_ENABLED=0)
make build-debug      # без -s -w
make test             # go test ./... -short
make vet              # go vet ./...
make fmt              # gofmt -l . (показать неотформатированное)
make checks           # vet + fmt + test
make test-integration # реальная сеть, за флагом (в CI не гонять)
make test-e2e         # сетевые проверки пайплайна run (тег e2e, вручную)
make clean            # удалить артефакты сборки
```

Перед сдачей любой правки обязательно зелёные: `go build ./...`, `go vet ./...`,
`gofmt -l .` (пусто), `go test ./... -short`. Пользователь код не читает — ревью
идёт только через тесты и поведение инструмента.

### Офлайн-режим

Модули лежат в локальном кэше, поэтому сборка/тесты работают так:

```bash
GOPROXY=off go build ./...
GOPROXY=off go test ./... -short
```

`go mod tidy` в этом окружении **не отрабатывает** (в кэше нет `.zip`/`.mod` для
части транзитивных зависимостей вроде `wintun`/`coninput`). Не «лечите» это
удалением зависимостей из `go.mod` — версии подобраны под кэш. На машине с сетью
достаточно один раз прогнать `go mod tidy`.

## Структура пакетов

| Пакет | Ответственность |
|---|---|
| `registration/` | неофициальный API Cloudflare, регистрация WARP, локальное хранение аккаунта |
| `tunnel/` | userspace WireGuard/AmneziaWG, хендшейк, `cdn-cgi/trace`, замер задержки, платформенный bind |
| `scanner/` | кандидаты (диапазоны × порты), предфильтр хендшейком, фильтр региона/colo, ранжирование |
| `dnscheck/` | проверка DNS через туннель |
| `config/` | сборка `.conf` (WARP-safe) и генераторы `I1` |
| `chain/` | цепочка «внешний AWG-туннель → WARP → Psiphon»: запуск внешнего warp-plus, проверка SOCKS5 |
| `core/` | пайплайн команды `run`: автомат состояний (endpoint → туннель → форвардер → страны → мониторинг), UDP-форвардер, поток событий |
| `vpn/` | системный туннель `run --tun`: TUN-устройство, мост TUN→SOCKS5 на gVisor netstack, DNS через цепочку, маршруты и откат (Linux) |
| `cli/` | CLI-команды `register`, `scan`, `dns-check`, `gen`, `chain`, `run`, `tun-revert` |
| `cmd/warpgen/` | точка входа, версия (подставляется через ldflags) |

Правило: логика — в пакетах, `cli/` только собирает их вместе и печатает.
Внутренние детали (`internal/`) не заводим — это локальный инструмент.

## Жёсткие инварианты — не ломать

### Конфиг WARP-safe (пакет `config`)

Обычный сервер Cloudflare не знает про AmneziaWG, поэтому менять формат пакетов
нельзя. Эти значения зафиксированы и проверяются тестами:

- `S1 S2 S3 S4 = 0`, `H1 H2 H3 H4 = 1 2 3 4` — выводятся в конфиг **всегда**;
- `MTU = 1280`;
- `PersistentKeepalive = 25` — **в секции `[Peer]`**, не в `[Interface]`;
- `I1` — имя поля строго заглавными, значение маскирует трафик (QUIC и др.);
- `DNS =` принимает **только IP** — имена резолвятся заранее;
- порядок полей `[Interface]`/`[Peer]` — как в `refconf/`.

Любые «улучшения» вроде своих `S`/`H`-значений или смены MTU ломают связь с
неизменённым сервером Cloudflare. Не делать.

### Туннель

- По умолчанию только userspace: обычные UDP-сокеты + netstack. **Никаких** root, TUN,
  `VpnService`, смены маршрутов.
- Единственное исключение — явный флаг `run --tun`: он поднимает системный TUN и
  меняет маршруты. Это изолировано в пакете `vpn/`, включается только флагом и не
  должно протекать в остальные команды (`register`, `scan`, `dns-check`, `gen`,
  `chain`, `run` без `--tun`).
- Задержку мерить **внутри туннеля**, не через ICMP/Ping (на Android ICMP
  ограничен и без прав показывает `?`).
- Не добавлять linux-only syscall'ы вне файлов с build tags
  (`tunnel/bind_linux.go`, `tunnel/bind_other.go`).

### Скан

- Диапазоны: `162.159.192.0/24`, `162.159.193.0/24`, `188.114.96.0/22`.
- Порты: `500, 1701, 4500, 2408`.
- Исключать регион `RU` и colo `DME`, `LED`, `KJA`.
- Полный перебор — тысячи пар IP×порт; за прогон проверяем `--max` кандидатов и
  останавливаемся после `--target` находок. Не превращать скан в долгий полный обход.
- Любой автоподбор endpoint (например, в `dns-check` без `--endpoint`) обязан быть
  ограничен по числу проверок и/или времени — иначе он уйдёт перебирать тысячи адресов.

### Пайплайн `run` (пакет `core`)

- `core` — библиотека: **никаких** `os.Exit`, чтения stdin, печати в stdout и
  глобального состояния. Остановка — только по `ctx`, диагностика — через
  `Config.Logf`. GUI и мобильные клиенты позже будут обёртками над этим API.
- Внешние зависимости (туннель, поиск endpoint, запуск warp-plus, проверка выхода,
  часы) заданы интерфейсами `Config`; фейки — в `core/fakes_test.go`. Новый сетевой
  эффект добавлять только через них, иначе автомат перестанет тестироваться офлайн.
- Внешний туннель отдаётся наружу только через UDP-форвардер, и только на loopback
  (проверяется в `NewForwarder`): форвардер даёт доступ к туннелю без аутентификации.
  `warp-plus` получает адрес форвардера в `-e`.
- MTU внешнего туннеля — 1280. Пакеты больше MTU считаем как `oversize` (счётчик +
  запись в `Logf`) и передаём как есть: процесс не роняем.
- События (`endpoint_selected`, `outer_up`, `outer_checked`, `forwarder_up`,
  `psiphon_starting`, `ready`, `degraded`, `failover`, `stopped`) — публичный
  контракт CLI и будущих клиентов: имена не менять без нужды, секретов в них нет.
- Сетевые проверки пайплайна — за тегом `e2e` (`core/e2e_run_test.go`), в
  `go test ./...` они не попадают. Обычные тесты — только loopback (локальное
  UDP-эхо) и фейки, без обращений во внешнюю сеть.

### Системный туннель `--tun` (пакет `vpn`)

- Системные эффекты — только через интерфейсы: `Config.TUN` в `core` (фейк —
  `core/fakes_test.go`), `vpn.Device`, `vpn.RouteManager`, `vpn.Executor`.
  `os/exec` живёт только в `vpn/routes_linux.go`; в остальном коде `vpn` никаких
  команд и syscall'ов быть не должно.
- TUN создаётся только через пакет `tun` из `amneziawg-go` (`CreateTUN`,
  `CreateTUNFromFile`) — никаких ручных ioctl.
- Маршруты применяются **только после** `ready`, иначе мост работает без прокси.
  Порядок запуска: цепочка → TUN и мост → маршруты → DNS; остановка — в обратном
  порядке, и всегда снимает маршруты (откат не зависит от отмены `ctx`).
- `RouteManager` помнит каждую выполненную команду и отменяет ровно их (обратный
  порядок); ошибка посередине откатывает применённое. `--dry-run` ничего не
  выполняет.
- После каждой выполненной команды журнал отката атомарно пишется в
  `~/.warpgen/state/<имя TUN>.st` (каталог — `Options.StateDir`), поэтому
  `kill -9` не оставляет применённое без записи. Команда `warpgen tun-revert`
  (`vpn.RevertTunState`) откатывает по журналу: невыполненные отмены остаются
  в файле (повтор продолжает с места сбоя), полностью откаченное удаляется.
  Шаги, чья отмена упала с «цели уже нет» (интерфейс уничтожен вместе с
  процессом), не считаются сбоем — см. `linuxTolerate`.
- Исключение `/32` внешнего endpoint — не оптимизация, а защита от петли: без него
  UDP-сокет внешнего туннеля уйдёт в наш же TUN. При смене endpoint обновлять.
- При failover TUN и маршруты **не снимать**: падающие соединения — это kill switch,
  трафик не должен уходить напрямую.
- UDP не проксируется, поэтому QUIC (`UDP/443`) отбрасывается молча (приложения
  должны откатываться на TCP), IPv6 уводится в blackhole, ICMP отбрасывается.
  Новое поведение для UDP сначала согласовать: точка расширения — `handleUDP`.
- События `tun_up`, `routes_applied`, `routes_reverted`, `dns_selected`, `dns_failed`
  — часть публичного контракта (наравне с остальными), имена не менять без нужды.
- Без root режим `--tun` обязан упасть с понятным сообщением до сети и до любых
  системных действий; проверка прав — `vpn.Options.CheckPrivileges` (Android её
  подменяет).
- Тесты `vpn` — офлайн: мост на двух стеках через фейковое устройство и поддельный
  SOCKS5, политика пакетов, выбор DNS, `RouteManager` на фейковом исполнителе. Тестов,
  которые создают TUN, меняют маршруты или просят root, в репозитории быть не должно:
  это ручной чек-лист e2e в README.

### Важно про регион RU (проверено на реальной сети)

Из России WARP **всегда** показывает внешним сервисам регион `RU`: Cloudflare
назначает выходной IP по геолокации клиента, а не по узлу `colo`. Замер: 100
endpoint'ов, 77 отдали trace, из них `loc=RU` — у всех; `ipinfo.io` и `ifconfig.co`
через туннель тоже видят Россию.

Решение пользователя: такие endpoint'ы **учитываются** (регион `RU` — не повод для
отбраковки). Реализовано так: `Options.StrictRegion` (по умолчанию `false`) и флаг
`scan --strict-region` для жёсткого режима; функция `regionStatus` применяет
политику, `ClassifyRegion` остаётся чистой. Исключённые colo DME/LED/KJA
отвергаются всегда — это вопрос доступности, а не региона. Не возвращать
безусловный фильтр `loc != RU` без явного запроса.

## Секреты и приватность

В git **не должно** попадать ничего с приватными ключами. Уже в `.gitignore`:
`refconf/`, `test-account.json`, `warpgen-account.json`, `*-account.json`, `*.conf`
(сгенерированные конфиги тоже содержат приватный ключ), `warpgen-chain/` (identity
warp-plus для команды `chain`), бинарники, `coverage.out`, локальные `.md`-документы.

При добавлении новых выходных файлов с ключами — сразу заносить в `.gitignore`.
Перед коммитом проверять, что в индекс не попали ключи и токены.

## Конвенции кода

- Комментарии и вывод CLI — на русском (пользователь русскоязычный).
- Возвращать явные ошибки с понятным сообщением, не глотать их.
- Каждую фазу закрывать тестами; чистые функции (парсинг, фильтры, генерация)
  тестировать unit-тестами, сетевые пути — интеграционным тестом за флагом.
- Форматирование: `gofmt`. Коммиты — по-русски, содержательные.

## Известные ограничения

- Если на устройстве активен другой VPN, скан пойдёт через него — проверять при
  выключенном VPN.
- Регистрация через туннель (когда API Cloudflare недоступен напрямую) требует уже
  существующего аккаунта (`--account`).
- Фичи вне v1: split-tunneling, кастомный клиент, GUI, релеи, warp-in-warp, MASQUE.
- Сквозная проверка «импортировали в AmneziaVPN → соединение поднялось → `loc != RU`»
  делается руками на устройстве.
