Код не менялся: `git diff` пуст, warp-plus — только релизный бинарник v1.2.6, warpgen — только запуск

## 1. Предусловие (проверено до тестов)

- Конфиг: `gen-psiphon-retest.conf` (сгенерирован warpgen), `Endpoint = 162.159.192.175:4500`, NODE **HEL**.
- `curl https://www.cloudflare.com/cdn-cgi/trace` → **`warp=on`**, `colo=HEL`, `ip=104.28.230.243` (AS13335 CLOUDFLARENET), `loc=RU`.
- `ip -brief addr show amn0` → интерфейс поднят, `ip route get 1.1.1.1` → `dev amn0`.
- Итог: colo HEL — не DME/LED/KJA, внешний туннель живой. (Примечание: AmneziaVPN сам назначает
  адреса интерфейсу — `122.87.0.0/32`, а не `Address` из файла; на работу это не влияет.)

## 3. Выводы

1. **Схема «WARP → Psiphon» из этой сети работает** — прежний вердикт («из этой сети непроверяема») снят:
   при живом внешнем AWG-туннеле (`warp=on`, colo HEL) warp-plus поднимает WARP, поверх него — Psiphon,
   и SOCKS-прокси `127.0.0.1:8086` отдаёт запрошенные страны за **7–16 с** с подтверждением по ip и ASN:
   NL, DE, SE, US — точно; PL — с оговоркой (см. вывод 4). Скорость через Psiphon 0.3–0.8 МБ/с,
   контроль без Psiphon — 3.45 МБ/с.
2. **Ожидание «теперь хендшейк проходит» подтвердилось, но узким звеном стал не он.** Внутри внешнего
   туннеля WARP-хендшейк проходит на всех 3 проверенных endpoint'ах (`Received handshake response`,
   `handshake complete`), а падение идёт на **внутреннем гейте warp-plus**: он делает HTTP **HEAD** к
   `--test-url` и требует ровно **200**, а Cloudflare сейчас отдаёт на HEAD `/cdn-cgi/trace` **404**
   (GET — 200; на `www.cloudflare.com` и `connectivity.cloudflareclient.com` HEAD=404, на `1.1.1.1`
   HEAD=302 при GET=200, `cp.cloudflare.com` — 204 на оба метода).
   Поэтому прогон «ровно как в задании» (и контроль, и `--cfon`) умирает через 21–42 с с
   `context deadline exceeded`, SOCKS-прокси не поднимается вообще — 4 из 4 прогонов без обхода (строки 1–3 и 12).
3. **Обход найден без правки кода:** `--test-url` с URL, у которого HEAD=200 (`http://example.com/`).
   С ним контроль поднимается за 6 с, а все 6 стран проходят стадию WARP (`connection test successful`).
   Причина — в самой проверке (HEAD + требование ровно 200) против текущего поведения
   `/cdn-cgi/trace`, а не в нашей сети: подтверждено на внешнем пути, и гейт не проходит
   ни на одном из 3 endpoint'ов. Бинарник — релиз v1.2.6 (январь 2025).
4. **Psiphon-этап проходит не всегда, и страна может не совпасть:** FI дважды из двух умер с
   `clientlib: tunnel establishment timeout` (60 с) при уже готовом WARP-этапе — это ровно звено (б);
   для PL один и тот же выход `57.128.192.119` (OVH) видится как PL у `ipinfo.io` и как FR у `ifconfig.co`,
   то есть по одному геосервису судить нельзя. Расхождение по стране — единственное за прогон;
   у остальных поднявшихся стран ip и страна совпали в двух сервисах.
5. **Внешний туннель держится, вложенность не при чём:** WARP-в-WARP сам по себе носит данные
   (на своём инструменте — DNS 71–134 мс внутри вложенного туннеля), `warp=on`/`colo=HEL` сохранялись
   до и после прогонов. Внутренний WARP без Psiphon выходит в Москве (RU) — страну меняет именно Psiphon.
   Ограничения замеров: `ipinfo.io` периодически отдаёт 429 (rate limit), поэтому у части прогонов
   подтверждение страны — по одному сервису; ключей и приватных данных в отчёте нет.
